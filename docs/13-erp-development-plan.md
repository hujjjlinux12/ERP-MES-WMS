# ERP 开发与验证计划

版本 1.0。以可在浏览器验证的业务流程为交付单位。每次只推进一个步骤。已保存的程序由学习者亲手编写；本文件提供施工顺序和验收标准。

## 1. 迭代顺序

| 步骤 | 开发顺序 | 浏览器验收 | 依赖 |
| --- | --- | --- | --- |
| E01 采购单列表 | 摘要 DTO → `GetAll()` → 列表 GET → 表格 → 点击复用详情 → 保存后刷新 | ，点击可见创建两行草稿后列表出现新单两行明细 | 已有物料、供应商、采购草稿 |
| E02 提交审批 | 定义状态和合法动作 → Service 校验 → API → 详情按钮 → 审计接入点 | 草稿提交后可审批，草稿直接审批返回 409 | E01 |
| E03 采购收货入库 | 仓库资料 → 收货单与来源行 → 迁移 → 库存流水与余额 → 事务及防重 → 收货页和进度 | 采购 10 分两次收 6、4；拒绝超收和重复入账 | E02 |
| E04 库存管理 | 余额查询 → 来源明细 → 移库 → 盘点 → 退货及冲销 | 同仓库余额可由流水重算；移库净变动为零 | E03 |
| E05 BOM 与生产 | BOM 版本和展开 → 工单快照 → 领退料 → 分批完工 → 成品入库 | 一张板卡工单和一张整机工单能完成模拟生产 | E04 |
| E06 品质与 MES | 待检状态 → 检验与放行 → 板卡及整机 SN → SMT 上料与绑定 → 返修 | 不合格整机不能入库；合格整机能追溯板卡与物料批次 | E05 |
| E07 销售与出货 | 客户 → 销售单 → 确认 → 出货与复核 → 退货 | 销售 10 台、分批出货；可查实际库存及已发数量 | E05，SN 出货依赖 E06 |
| E08 模拟财务 | 价格和金额规则 → 发票与对账 → 收付款核销 → 凭证和期间 | 应收应付与核销来源能回查，凭证借贷平衡 | E03、E07 |
| E09 报表与交付 | 业务指标 → 报表、导出与追溯 → 打包 → 数据库恢复演练 | 从报表查到来源单据，恢复后关键余额一致 | 对应业务模块 |

权限贯穿开发：E02 明确审批角色，完成首条闭环后增加登录和后端授权；其余模块随新操作配置角色。公共导航和审计随页面与动作同步增加。采购金额、采购申请、询价、MRP 等专题在核心流程跑通后再排入对应模块。

## 2. 每一步怎样动手

1. **写一个业务例子**。说明谁在什么状态做什么、成功后改变哪些数据、失败要提示什么。
2. **画数据关系**。先区分单头、明细和来源单据，列出必填、外键和唯一约束。模型变化时先看迁移的 `Up()`，再应用数据库。
3. **编写后端**。先写 DTO 和 Service 的输入、校验、返回，再由 Controller 映射 HTTP。接口先单独验证，确定状态码和 JSON。
4. **接入页面**。做列表、详情和提交；从 Network 验证请求地址、方法、参数和响应。写操作后按实际需要刷新相关列表。
5. **按例子验收**。至少检查成功和一个失败分支。库存过账额外验证并发、重复请求和事务失败时无部分写入。保存验收证据及发现的问题。

## 3. 当前动手卡：E01

现有 `PurchaseOrderSummary` 已创建。先完成 `PurchaseOrderService.GetAll()`，用 `OrderByDescending` 排序、`Select` 投影为摘要并用 `ToList()` 执行查询。然后在 `PurchaseOrderController` 增加无路径参数的 `[HttpGet]`，调用服务。保留已有 `GET /purchase-orders/{id}`。本步不涉及数据库结构变更。

后端验证：重启应用并访问 `/api/purchase-orders`，已有单据返回 200 和数组，按 ID 倒序，`lineCount` 与详情一致。随后在 `purchase-orders.html` 增加采购列表，页面加载和创建成功后请求列表，查看按钮调用已有详情查询。点开任一行，核对供应商和明细是否对应。空列表给出清楚提示，非法 ID 显示不存在。

## 4. 贯通验收样例

| 场景 | 准备及动作 | 预期 |
| --- | --- | --- |
| P1 采购入库 | 供应商 `SUP-001`，物料 `PCB-001` 订购 10；提交审批，先收 6 再收 4 | 两张收货单可回查同一采购行，库存净增 10，剩余 0 |
| P2 规则失败 | P1 只收 6 时尝试再收 5；或用相同请求键重发第一笔 | 超收拒绝，重复请求不新增有效收货或流水 |
| P3 生产与追溯 | 建板卡和整机 BOM，按工单领料、报工和检验，再完工入库 | 领料和入库来源可查；从整机 SN 回查板卡与检验记录 |
| P4 销售交付 | 客户订 2 台，从合格成品库分两次出货，每次 1 台 | 销售单剩余量归零，库存减 2，序列号不能重复出货 |
| P5 对账 | 对出货生成模拟发票 100，分次收款 60 和 40 | 未结余额归零，金额及来源均可回查 |
| P6 恢复 | 备份数据库，在独立目录恢复并启动应用 | 采购单、出货单及库存汇总能与备份时结果核对 |

验收记录建议使用“用例编号、操作、预期、实际、结果、证据”六项。失败先区分页面 JavaScript、HTTP 状态、服务规则和数据库约束。模型改动前后分别检查迁移与业务场景。
