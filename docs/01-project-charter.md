# 项目章程与交付计划

## 1. 目标与约束

建立从采购订单到收料、库存、生产工单、生产报工、成品入库及出货的业务闭环；做到库存有依据、整机可追溯、异常可处理、责任可审计。

已知约束：400 人、6 条线、日均 500 台、2 名开发者、无既有 ERP/财务系统。员工数不等于并发用户数，产量也不能直接换算为系统吞吐量；性能指标需要调研。

## 2. 一期范围

包含组织与权限、物料与 BOM、供应商与客户、采购与来料检验、仓库收发存、盘点、生产工单、投料与关键工序报工、基础品质与返修、整机追溯、销售订单与出货、基础经营报表。

一期采购和销售支持数量、单价、金额及业务对账导出，但不作为法定财务账簿。总账、税务、工资、固定资产、完整成本核算列入后续独立范围；当前没有财务软件，必须另行确定财务记账方案和责任人，不能把出入库流水等同于财务记账。

二期候选：MRP、产能计划、供应商协同、售后 RMA、设备自动采集、成本核算。APS、复杂自动化仓储和微服务拆分需要收益与维护能力评估。

范围补充：用户已明确包含 SMT。板卡生产工单、料卷管理、上料校验、板卡品质及板卡到整机的追溯纳入一期范围讨论，详见 SMT 补充文档。已确认 SMT 管理功能由本项目新建。设备自动采集与设备联锁单独评估。原 6–9 个月估算尚未计入已确认的 SMT 详细工作量，必须在调研后重估。

## 3. 组织与责任

| 角色 | 责任 |
| --- | --- |
| 工厂项目负责人 | 确认目标、资源、跨部门冲突、上线与验收 |
| 采购/仓库/生产/品质/销售业务负责人 | 提供现行单据，确认规则，参与验收和培训 |
| 开发人员 A | 建议负责平台、ERP 与核心数据设计 |
| 开发人员 B | 建议负责 WMS、MES 与现场交互 |
| 两名开发者共同 | 代码审查、接口协作、测试、发布与故障处理 |
| 财务负责人或指定外部服务方 | 确认金额、对账、账务衔接与财务范围 |

开发分工是建议，人员姓名和最终职责待确认。业务负责人需要稳定投入时间，不能由开发者代替业务验收。

## 4. 阶段与交付门槛

以下是用于讨论的工作分解，不是交付承诺；2 人团队初步预留约 6–9 个月，外部硬件、需求变化及业务配合可能显著影响工期。详细估算在业务蓝图评审后完成。

| 阶段 | 参考时间 | 交付物 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| 现状调研 | 2–3 周 | 流程、单据样本、问题与数据清单 | 业务负责人确认现状 |
| 蓝图与详细设计 | 3–4 周 | 范围、原型、详细需求、数据与接口设计 | 核心规则及验收标准获确认 |
| 基础与采购仓储 | 6–8 周 | 权限、主数据、采购、收发存、盘点 | 核心库存场景测试通过 |
| 生产与品质 | 6–8 周 | 工单、序列号、报工、测试结果、返修 | 单台产品全流程可追溯 |
| 销售出货与联调 | 3–4 周 | 订单、拣货、包装、出货、报表 | 端到端业务验收通过 |
| 单线试点与推广 | 4–6 周 | 培训、切换、恢复演练、试点记录 | 对账及关键缺陷关闭后逐线推广 |

阶段有依赖，不能把开发阶段视为互不相关的独立项目。每个阶段先实现一条真实业务链，再逐步覆盖异常场景。

## 5. 成功标准

- 采购、收货、检验、入库、领料、生产、成品入库和出货之间可关联查询。
- 库存余额能由期初和有效库存流水重算，账实差异经过盘点审批处理。
- 任一整机 SN 可查关键投料、工序、测试、返修、包装和出货记录；具体追溯粒度待确认。
- 关键操作有权限与审计；备份恢复通过演练。
- 业务负责人按验收用例签字。准确率、操作耗时和稳定运行时长在调研后填入量化目标，不提前编造。
