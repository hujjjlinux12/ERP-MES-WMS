# 显示器制造 ERP–MES–WMS 模块设计与实施路线

版本 0.1。适用项目为 `LearningErp.Api/Erp`，用于本地模拟和学习。本文记录当前进度与下一步设计，早期文档保留为需求和架构参考。后续按“业务场景 → 规则 → 表与接口 → 页面 → 验收”完成一个功能，再进入下一个功能。

## 1. 当前基线

| 能力 | 已有代码和页面 | 当前边界 |
| --- | --- | --- |
| 工作台 | 首页有物料、供应商和采购入口，已有共用导航和样式 | 采购仍是独立页面，尚无单据列表 |
| 物料 | 查询列表、按编码查询、按状态筛选、新增、修改、启停、删除 | 已有采购引用的记录应走停用，删除被引用物料时的业务提示待完善 |
| 供应商 | 查询和新增 | 编辑、停用及更多档案字段待设计 |
| 采购单 | 创建草稿、按 ID 查看单头与明细 | 尚无列表、审批和收货；数据库 ID 作为当前单据标识 |
| 数据 | SQLite、EF Core 迁移；采购单关联供应商，明细关联物料和单头 | 当前以单工厂和本地数据库练习，后续逐步引入仓库、批次和事务规则 |

用户已确认工作台可打开，采购草稿链路已跑通。本次基线依据现有源码与已完成的手工验证记录，不视为对全部按钮重新验收。

## 2. 业务主线与系统边界

```mermaid
flowchart LR
    A[ERP 物料与供应商] --> B[ERP 采购单与审批]
    B --> C[WMS 收货与库存入账]
    C --> D[ERP BOM 与生产工单]
    D --> E[WMS 备料与发料]
    E --> F[MES SMT 板卡与整机装配]
    F --> G[MES 检验与放行]
    G --> H[WMS 成品入库]
    H --> I[ERP 销售订单与 WMS 出货]
```

- **ERP** 管主数据、采购与销售单据、BOM 和生产工单，回答买什么、做什么、卖什么。
- **WMS** 管库存实物的收、发、移、盘，以及仓库、库位、批次和库存状态。一个库存动作只记一次流水。
- **MES** 管工单执行、工位、报工、品质及追溯。SMT 属于 MES 的板卡生产环节，与整机装配共享工单和追溯体系。
- **公共能力** 管登录、角色、操作日志和导航。模拟初期可以先用明确的操作入口验证规则，正式加入角色后再从身份信息取得操作者。

库存数量由库存模块统一更新。采购、出货、生产完工等模块提交明确的库存业务动作，各自保留单据关联。采用线边仓时，发料代表转移位置，实际投料代表消耗，两个动作分别记录。

## 3. 模块清单与验收目标

| 领域 / 模块 | 页面与主要对象 | 首个可验收的业务场景 |
| --- | --- | --- |
| 公共 / 工作台 | 首页、模块导航、操作反馈；用户、角色、审计日志 | 从工作台进入单据列表和详情；有权限控制后，仓管角色无法审批采购单 |
| ERP / 物料 | 物料列表和详情；`Material`、基本单位、启用状态 | 停用后仍能查历史资料，创建采购单时拒绝该物料 |
| ERP / 供应商与客户 | 供应商列表、客户档案；`Supplier`、`Customer` | 采购单只能引用已有供应商；销售单只能引用已有客户 |
| ERP / 采购 | 列表、详情、创建、提交与审批；`PurchaseOrder`、`PurchaseOrderLine` | 从列表查到草稿，提交并审批；审批前不能收货 |
| WMS / 仓库与收货 | 仓库、库位、收货单；`Warehouse`、`Location`、`Receipt` | 同一采购行能分批收货，累计量不得超过订购量 |
| WMS / 库存与盘点 | 库存余额、流水、移库、盘点；`StockBalance`、`StockLedger`、`StockCount` | 收货后余额增加且可查来源，盘点差异通过调整单记录 |
| ERP / BOM 与工单 | BOM 版本、生产工单；`BomVersion`、`BomLine`、`WorkOrder` | 整机 BOM 能引用板卡；已下达工单保持原 BOM 版本 |
| WMS / 生产物流 | 备料、领退料、成品入库；领料单、退料单、成品入库单 | 按工单发料，数量超出可用量时拦截；成品入库可回查工单 |
| MES / 整机执行 | 工序报工、整机序列号；`RouteStep`、`UnitSerial`、`OperationRecord` | 一台整机按必经工序完成，重复扫码不重复计产 |
| MES / SMT | 板卡工单、料卷、站位上料、板卡过站；`Reel`、`MaterialLoadingRecord`、`BoardSerial` | 错料被拦截，合格板卡能绑定整机，能查询关联的料卷或批次范围 |
| MES / 品质与返修 | 来料检验、整机测试、不良及复检；`Inspection`、`TestResult`、`Repair` | 测试不合格的整机需返修并复检放行后才可正常入库出货 |
| ERP / 销售 | 客户订单及发货进度；`SalesOrder`、`SalesOrderLine` | 保存客户订单，能查询已发和待发数量 |
| WMS / 包装与出货 | 拣货、箱码、出货复核；`Package`、`Shipment` | 同一整机不能重复出货，出货后可由客户订单找到对应整机 |
| 公共 / 报表与追溯 | 采购进度、库存流水、工单进度、追溯查询 | 从整机查板卡、品质和出货，从指定料卷或批次反查影响范围 |

模拟范围暂定单工厂，采购初版只处理整数数量。分批收货首版先验证“已批准采购行 → 直接入库”；来料质检阶段再扩展成“待检 → 放行／隔离”。SMT 先按人工扫码设计，有可靠的设备数据后再细化采集和机台联锁。精确到单板的元件追溯依赖实际绑定证据，只有工单发料记录时应展示候选范围。完整财务、税务和高级排产留作独立专题。

## 4. 前后端设计约定

保留当前 HTML、CSS、JavaScript 与 ASP.NET Core 同源的方式。导航随模块增加，管理模块优先采用“列表 → 详情 → 业务操作”的结构。列表放查找与筛选，详情显示单据状态和来源，业务按钮发请求并在页面显示成功或明确的错误。采购创建页已有的表单可以继续使用。

| 层次 | 职责 |
| --- | --- |
| 页面 | 收集输入、显示列表和详情、提交 API、刷新结果 |
| Controller / DTO | 绑定参数和请求数据，把结果转成 HTTP 状态及 JSON |
| Service | 检查业务规则、推动单据状态、协调一次业务操作的写入 |
| EF Core / SQLite | 管理实体映射、外键、唯一约束、迁移和持久化 |

修改已应用的表结构时，生成一条新迁移。先看 `Up()`，确认改动目标，再运行 `dotnet ef database update`。数据库业务约束和 API 错误提示一起设计。例如外键保护被引用的物料，API 则返回明确的冲突原因，页面可以提示改用停用。

| 步骤 | 做完后可以演示什么 | 依赖 |

| E04 档案完善与异常处理 | 供应商维护、物料引用冲突提示、采购退货或收货冲销 | E03，先把回退规则写清楚 |
| E05 BOM、工单和领退料 | 从板卡与整机 BOM 创建工单，按工单领退料 | 物料、库存，BOM 版本规则 |
| E06 MES、品质和 SMT | 料卷上料防错、板卡与整机绑定、报工及返修放行 | E05，先一款板卡、一条模拟产线 |

| E08 权限、报表和部署演练 | 分角色操作，从报表回到业务单据，演练数据库备份与恢复 | 已跑通核心闭环。角色和审计可以在单据审批阶段先逐项引入 |

## 6. 下一步详细设计：E01 采购列表与详情

**目标。** 用户进入采购页后就能找到已有采购单，点开看明细。手动输入 ID 仍可用于测试或直接查询。现有 `POST /api/purchase-orders` 和 `GET /api/purchase-orders/{id}` 可以直接复用。

**新增接口。** `GET /api/purchase-orders` 返回 `200` 和摘要数组。空库返回 `[]`。第一版按采购单 `Id` 倒序排列，用 ID 展示录入顺序，不把它当作业务日期。列表查询不加载整份明细，查看时再调用详情接口。

| 响应字段 | 说明 |
| --- | --- |
| `id` | 采购单 ID，用于打开详情 |
| `supplierCode` | 供应商编码 |
| `status` | 单据状态，目前已实现 `Draft` |
| `lineCount` | 明细行数，例如两种物料为 2 行，不等于数量之和 |

```json
[
  { "id": 3, "supplierCode": "SUP-001", "status": "Draft", "lineCount": 2 }
]
```

**页面。** 在采购页增加“采购单列表”卡片，显示 ID、供应商、状态、明细数和“查看”按钮。点击查看时填写现有的 ID 输入框，并使用原来的查询逻辑。草稿保存成功后刷新列表。列表为空时显示“还没有采购单”，请求失败时显示错误并保留查询入口。

**动手顺序。** 先定义摘要 DTO，再在服务中用 LINQ 投影出所需字段，随后加控制器的无参数 `GET`。先用浏览器打开接口确认 JSON，再接采购页的表格。这一步只读现有表，无需生成迁移。

**验收用例。**

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| E01-01 | 查询已有两张单的采购列表 | ID 大的在前，每行显示正确供应商、状态和明细数 |
| E01-02 | 点击一张采购单的“查看” | 详情展示同一 ID 和对应的物料与数量 |
| E01-03 | 在页面新建一张带两行明细的草稿 | 创建成功后列表自动出现新单，明细数为 2 |
| E01-04 | 查不存在的 ID | 页面展示 404 或“采购单不存在”，列表仍可使用 |
