# 工程与质量规范

## 1. 交付流程

遵循可追踪的工程实践，不宣称已经获得任何标准认证。每项需求建立唯一编号，关联设计、任务、代码变更、测试与验收记录。

需求状态：草案 → 已评审 → 已批准 → 开发中 → 待验证 → 已验收。业务规则改变需要记录原因、影响范围、工期变化及批准人；不能只改聊天记录。

## 2. 开发约定

- 主分支保持可发布，小分支按需求或缺陷提交；另一名开发者审查关键变更。
- 库存、序列号、权限、审批、金额和数据迁移属于重点审查范围。
- 使用统一代码格式、命名与静态分析；依赖锁定，更新需验证。
- 开发、测试、生产环境隔离；测试数据不直接使用敏感生产数据。
- 每次合并运行构建、自动化测试和迁移检查；不得将失败检查当作通过。

## 3. 测试策略

| 层次 | 重点 |
| --- | --- |
| 单元测试 | 数量换算、状态转换、放行、替代料和金额规则 |
| 数据库集成测试 | 事务回滚、并发扣减、唯一约束、重复请求、冲销 |
| 接口与权限测试 | 越权读取、越权审批、非法参数、重复调用 |
| 业务端到端测试 | 采购 → 收货 → 检验 → 领料 → 生产 → 入库 → 出货 |
| 异常流程测试 | 部分收货、隔离、退料、报废、返修、拆包、盘点及停线补录 |
| 现场验收 | 实物标签、扫码枪、打印机、终端和业务人员真实操作 |
| 运行验证 | 实际负载、备份恢复、磁盘不足、服务重启、网络中断 |

关键质量用例：两人同时领取最后一批库存；同一终端重复发送完工请求；不合格整机尝试出货；BOM 更新后旧工单继续执行；备份恢复后核对库存与追溯链。

## 4. 完成定义

需求具备确认记录；设计与业务规则一致；代码审查完成；相关测试通过；异常与权限路径已验证；必要迁移和回退方案可执行；用户文档已更新；业务负责人验收。没有运行的检查必须明确标记“未执行”。

## 5. 上线与切换

1. 清理并确认物料、BOM、供应商、客户、库位及期初批次。
2. 演练导入，核对数量、金额与追溯信息；保留源表和校验报告。
3. 单线试点，指定当班业务负责人和问题处理人。
4. 正式切换确定停账时间，盘点签字，导入期初，核对后开放新业务。
5. 明确每类业务唯一记账入口；纸质应急记录设编号，补录后逐单核销。
6. 推广至其余产线前复核缺陷、账实差异与培训结果。

上线门槛：关键业务验收通过；阻断性缺陷关闭；角色权限复核完成；恢复演练通过；现场设备可用；期初账实确认；支持联系人和应急流程到位。阻断性缺陷包括重复出货、超扣库存、越权和追溯丢失。

## 6. 运维交接

交付部署说明、配置清单、备份策略、恢复记录、监控告警、常见故障手册、账号交接和版本记录。RPO、RTO、备份频率、保存期与值守时间需由负责人确认并落实资源。
